## Chapter 10: Alerting and Production Governance for ML Systems — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Lakehouse Monitoring vs Databricks SQL Alerts — division of responsibility? | Lakehouse Monitoring computes profile/drift metrics into Delta tables. SQL Alerts query those tables on a schedule and fire notifications/webhooks when thresholds are crossed. Exam tip: monitoring computes, alerting reacts. |
| 2 | How do you route a drift alert to trigger an automatic retraining Job? | Attach a Databricks SQL Alert to the monitor's drift metrics table; set its notification destination to a webhook that calls the Jobs API to run the retraining Job. Exam tip: alerts notify, they don't natively run Jobs. |
| 3 | What is the escalation sequence tested for production ML remediation? | Alert -> Investigate -> Retrain -> Validate -> Promote. Exam tip: any answer that promotes without validating is the wrong-answer trap. |
| 4 | What UC concept replaced Staging/Production stages for registered models? | Aliases — mutable named pointers (e.g., 'Champion', 'Challenger') to a specific model version. Exam tip: exam answers referencing 'transition to Production stage' for UC models are outdated/wrong. |
| 5 | Command to programmatically point a Production alias at a validated model version? | `MlflowClient().set_registered_model_alias(name, alias, version)`. Exam tip: use alias APIs, not the deprecated `transition_model_version_stage` for UC-registered models. |
| 6 | Where does the audit trail for UC model version alias changes and permission grants live? | Unity Catalog audit logs — capturing alias assignments, permission changes, and access history per model version. Exam tip: this is the governance answer whenever a scenario asks for 'who changed what and when'. |
| 7 | Which Asset Bundle resource deploys a retrain-validate-promote pipeline as code? | A `resources.jobs` block in `databricks.yml`, with chained tasks via `depends_on`, deployed via `databricks bundle deploy`. Exam tip: DABs make the pipeline reproducible across dev/staging/prod targets. |
| 8 | Scenario phrase 'react automatically when a metric crosses a threshold' maps to which category? | Monitoring + Automation (alerting-triggered response). Exam tip: 'react to threshold' = alerting; 'gate before promotion' = testing; 'stage/alias transition' = lifecycle. |
| 9 | Difference between 'testing' and 'monitoring' language in exam scenarios? | Testing = pre-deployment validation gates (unit/integration/champion-challenger comparison) before promotion. Monitoring = post-deployment observation of live metrics (drift, latency, quality) after the model is serving. |
| 10 | What must happen between 'retrain' and 'promote' in the escalation strategy? | Validate — evaluate the new model version against the current Champion on a held-out/recent dataset before moving the alias. Exam tip: skipping this step is the standard distractor. |
| 11 | Can a Databricks SQL Alert directly change a model alias? | No — SQL Alerts only send notifications (email, Slack, webhook). A downstream process (e.g., a Job) triggered by the webhook must call MlflowClient to change the alias. Exam tip: alerts notify, Jobs act. |
| 12 | What columns commonly back drift-based SQL alerts in Lakehouse Monitoring output? | `js_distance` (Jensen-Shannon distance), chi-squared test p-value, KS-test statistics, and `percent_null`, computed per time window in the profile/drift metrics Delta tables. Exam tip: alerts query these precomputed tables, they don't recompute stats. |
