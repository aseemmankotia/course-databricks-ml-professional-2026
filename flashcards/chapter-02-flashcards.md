## Chapter 2: Scaling and Hyperparameter Tuning: pandas Function API, Optuna, and Ray — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | applyInPandas vs mapInPandas — key structural difference? | applyInPandas requires groupBy() first and runs the function once per group, returning one pandas DataFrame per group. mapInPandas has no grouping requirement and instead operates on an iterator of pandas DataFrames representing partitions. Exam tip: use applyInPandas for per-key model training; mapInPandas for partition-level transforms. |
| 2 | Optuna default sampler when calling optuna.create_study()? | TPESampler (Tree-structured Parzen Estimator) — a Bayesian optimization sampler. RandomSampler, GridSampler, and CmaEsSampler must be explicitly selected. |
| 3 | Is Optuna's study.optimize() driver-bound or cluster-bound by default on Databricks? | Driver-bound. Trials run on the driver node, optionally parallelized across driver cores with n_jobs, but never distributed to worker nodes. Exam tip: use Ray Tune for cluster-wide distributed HPO. |
| 4 | Which API call sets up a Ray cluster on top of a Databricks Spark cluster? | ray.util.spark.setup_ray_cluster(). This converts Spark worker resources into a Ray cluster for Ray Tune / Ray Train distributed jobs. |
| 5 | When should you choose pandas Function API over Ray Tune? | When the workload is embarrassingly parallel — many independent small models (one per store/device/customer), each fitting comfortably on one executor. Ray Tune is for distributing hyperparameter search or large-model training, not simple per-group training. |
| 6 | Ray Tune vs Ray Train — what's the distinction? | Ray Tune distributes hyperparameter search trials across a Ray cluster. Ray Train distributes the actual training computation of a single large model (e.g., across multiple GPU nodes). Exam tip: pick Ray Train when one model doesn't fit or train fast enough on one node. |
| 7 | What must you always specify when using applyInPandas or mapInPandas? | An explicit output schema (StructType or DDL string). Spark needs the resulting schema declared up front since the pandas function executes lazily per group/partition. |
| 8 | Optuna trial API — how do you suggest a hyperparameter value? | trial.suggest_float('lr', 1e-5, 1e-1, log=True), trial.suggest_int('depth', 2, 10), trial.suggest_categorical('optimizer', ['adam','sgd']). Exam tip: log=True for parameters spanning orders of magnitude like learning rate. |
| 9 | Scenario: 5,000 SKUs, one small model each. Best scaling approach? | pandas Function API with applyInPandas grouped by SKU — distributes independent model training across executors. Ray/Optuna add unnecessary distributed-tuning overhead for this embarrassingly parallel pattern. |
| 10 | Driver-bound tuning risk on Databricks? | Running many Optuna trials only on the driver underutilizes worker nodes and bottlenecks as trial count or model size grows. This is the core trade-off tested versus Ray Tune's cluster-bound distribution. |
| 11 | How can Optuna's TPE sampling be used inside a cluster-distributed search loop? | Ray Tune can wrap Optuna as a search algorithm (ray.tune.search.optuna.OptunaSearch) while distributing trial execution across the Ray cluster — combining Optuna's sampling intelligence with Ray's cluster-scale execution. |
| 12 | mapInPandas function contract? | Receives an iterator of pandas.DataFrame (one per partition, no grouping key context) and must yield pandas DataFrame(s) matching the declared output schema. Exam tip: unlike applyInPandas, there's no group key available inside the function. |
